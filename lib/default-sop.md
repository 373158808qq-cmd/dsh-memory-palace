# 协作 SOP + 工程规范（出厂基础版）

> **这一份只保留「东西放哪 / 目录结构」这套硬约定** —— 因为台账、档案、每轮注入这些机制**全靠它对齐**，换一套就转不起来。
> **其余规矩（怎么沟通、怎么验证、怎么复盘）属于你自己**：在设置页「记忆系统」卡里点【分析我的文档】，
> 选一份你自己的协作说明/交接文档，系统会用 DSH 的模型提炼出**你专属的 SOP**。

## 一、东西放哪（硬约定，别改）

**判据一句话**：**"它只服务于某一个项目吗？"** —— 是 → 进 `<项目名>/`；否（多项目共用／整个工作区的事）→ 留根。

- **工作区根 = 容器，不是项目**：只放"整个工作区共用"的东西（下面白名单）。
- **新项目**：先问用户项目名 → 根下建 `<项目名>/` → 里面建台账 + 规则 → 项目的一切（代码/数据/文档/交付物）**只放这个文件夹**。
- **根目录白名单**：`AGENTS.md`（工作区地图）｜`<项目名>/`｜`plugins/<包名>/`｜`backups/<项目名>-<日期>/`（**必须带项目前缀**）｜`.ptmp/`（临时产物，随时可删）｜`docs/`｜`node_modules/` 等依赖目录。

**每个项目文件夹里放什么**：
```
<项目名>/
  PROJECT_LEDGER.md           # 台账 = 当前状态（每轮注入，有上限，别写历史流水）
  PROJECT_LEDGER_ARCHIVE.md   # 档案 = 根因/过程/实测数字/证据（不注入，不设上限）
  AGENTS.md                   # 只对这个项目成立的规矩
  产出物/                      # 交付物（docx / 报告 / 截图）
  （代码与数据）
```

**两个 `AGENTS.md` 的分工**（同名是机制要求：只自动注入 `AGENTS.md` / `PROJECT_LEDGER.md` 这两个文件名）：
**工作区根** = 整个工作区的地图 + 通用规矩；**项目里** = 只有这一个项目的规矩（与根那份**叠加**）。
判据 = **"换个项目还成立吗？"** 成立 → 根；不成立 → 项目。

## 二、文件生成 / 临时物

- **中文文本、JSON/`package.json` → 一律用 `read`/`write`/`edit` 工具**（PowerShell 写 JSON 会带 BOM、裸替换会乱码）。
- 脚本用 **ASCII 路径**；中文内容放 **UTF-8** 文件。
- **临时文件进 `.ptmp/`，交付物进 `产出物/`**。

## 三、台账 / 档案 两文件纪律（机制依赖，务必守）

- **台账只放"当前状态"**：大进度／未验收／待办／铁律／指针；**做完的细节一律进档案**。
- **指针要指得到**：`vault:<分区>#<标题>` 或 `file:<路径>#<标题>`，**用标题当锚点，别用行号/id**（重跑切块就全变）。
- 写完台账/档案后，**要让 vault 同步跟上**（设置页有「重建/同步」按钮或命令行同款命令），否则检索里还是旧内容。
