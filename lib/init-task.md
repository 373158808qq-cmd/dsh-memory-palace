# 初始化任务书 —— 一键初始化（骨架 → 嵌入器 → 显示层 → 记忆）

> 这是**新会话的第一条指令**（由「记忆系统 · 初始化」卡片的【一键初始化】按钮填入）。
> 用户已经装好插件、点了那个按钮。**你的任务不是"演示"，是"建好"**。
> **做完之后，那张卡上的 5 行应该全是 ✓。**

## ★第 0 步：用提问工具问用户四件事（别自己猜）★

顺序不能变：**根目录 → Ollama → 模型 → Obsidian**。用你的提问工具（`ask_user_question`）**一次问一个**，
**选项给全**，让用户"点一个"或者"自己填"。先看现状：

```bash
node "{{PLUGIN_LIB}}/init-cli.mjs" status     # 现在到哪一步了（JSON）
node "{{PLUGIN_LIB}}/init-cli.mjs" detect     # 检测 Ollama + 模型（只读探测，永远 exit 0）
```

> `{{PLUGIN_LIB}}` 已经替你填成实际路径，**照抄就行**。
> 探测类命令（`status`/`detect`/`obsidian-status`）**exit 0 不代表"装好了"** —— 结果在 JSON 里，你自己判。

### 问 1／4：工作区根目录在哪？

DSH 自己登记过的工作区 + 最近用过的（你直接把这些当**答案选项**甩给用户）：

```
{{WORKSPACES}}
```

选项就这么给：① 用第 1 个　② 用第 2 个　③ **我自己填一个路径**。
他选/填完，建骨架（**只建不存在的，同名一律跳过**）：

```bash
node "{{PLUGIN_LIB}}/init-cli.mjs" skeleton --root "<他给的绝对路径>"
```

把输出里的 `created` 与 `skipped` **原样念给他听**；**绝不覆盖任何已存在的文件**。

### 问 2／4：Ollama 怎么走？

先 `detect` 看现状，再把**这三个选项原文照给**：

- **A. 已经装了** → 让他给 `ollama.exe` 的路径（或它所在的目录）：
  `node "{{PLUGIN_LIB}}/init-cli.mjs" ollama-locate --path "<路径>"`
- **B. 帮我装** → **必须先经他同意**（这会把 OllamaSetup.exe 下下来并静默装进他机器）：
  `node "{{PLUGIN_LIB}}/init-cli.mjs" install-ollama`　→ 装完再 `detect` 复检一次
- **C. 用云端 API，不装本地** → 记一笔：`node "{{PLUGIN_LIB}}/init-cli.mjs" use-api`

### 问 3／4：嵌入模型怎么走？

- **A. 本地模型已经有了** → 让他给模型名（默认 `qwen3-embedding:0.6b`）：
  `node "{{PLUGIN_LIB}}/init-cli.mjs" mark --json '{"model":"<名字>"}'` → 再 `detect` 复检
- **B. 帮我拉** → **先说清"要下约 600 MB"**，他同意后再跑：
  `node "{{PLUGIN_LIB}}/init-cli.mjs" pull-model`
- **C. 用云端 API**

### 问 4／4：Obsidian 怎么走？（⑧ 显示层）

**为什么现在就要问**：记忆视图（`<根目录>/memory/记忆视图/`）就是 Obsidian 的"库"，
**库得先登记好、目录得先存在**，等记忆建完、视图一生成，打开就是一棵完整的树。
所以"问 + 装 + 登记库"都排在**建记忆之前**，只有"打开"放在最后（那时树才是满的）。

先看现状：`node "{{PLUGIN_LIB}}/init-cli.mjs" obsidian-status`，再把**三个选项原文照给**：

- **A. 已经装了** → 让他给 `Obsidian.exe` 的路径（或它所在的目录）：
  `node "{{PLUGIN_LIB}}/init-cli.mjs" obsidian-locate --path "<路径>"`
- **B. 帮我装** → **必须先经他同意**（这会 `winget install Obsidian.Obsidian`，往他机器上装程序，可能几分钟）：
  `node "{{PLUGIN_LIB}}/init-cli.mjs" install-obsidian`
  装不上就照它给的出路说（自己去 obsidian.md 装 / 用别的编辑器看 .md），**别卡住整个流程**。
- **C. 不用 Obsidian** → 正常收尾时**不要**打开它，只告诉他视图文件夹在哪。

选完 A 或 B 之后，**立刻把库登记好**（这一步会建出视图目录并写进 Obsidian 的库列表）：

```bash
node "{{PLUGIN_LIB}}/init-cli.mjs" obsidian-register
```

> 顺带说一句：这些 .md 只读副本**用任何编辑器都能看**（VS Code / Typora / 记事本）；
> Obsidian 只是"看起来最舒服 + 有树状图和关系图"的那个选择，不是必需品。

### ★如果上面选了 API（2-C 或 3-C）：先停在这儿，别往下做★

1. 明确告诉他：**去 DSH 的「设置 → 记忆 → 嵌入器」，选「云端 API」，填 API 地址 / 模型名 / Key，保存后点【测试】。**
2. 记一笔：`node "{{PLUGIN_LIB}}/init-cli.mjs" use-api --model "<模型名>"`
3. **等他说"好了"** —— 他没回话之前，你**不要**自己往下走（库建不起来：嵌入器还没配好）。
4. 他说"好了"之后跑 `node "{{PLUGIN_LIB}}/init-cli.mjs" detect` 确认通了，**再**继续下面第五节。

## 一、做完的标准（四类产物，缺一不算完）

1. **核心记忆三份**（每轮注入）：`~/.dsh-memory/SOP.md`（规矩）／`USER.md`（画像）／`MEMORY.md`（长期记忆）
2. **工作区结构**（按出厂 SOP）：每个项目一个文件夹 —— `PROJECT_LEDGER.md`（台账＝**当前状态**）／`PROJECT_LEDGER_ARCHIVE.md`（档案＝细节、数字、证据）／`AGENTS.md`（只对该项目成立的规矩）；工作区根 `AGENTS.md`（地图）
3. **指针体系**：`<工作区>/memory/INDEX.md`（项目总目录）／`<工作区>/memory/VAULT_INDEX.md`（位置总目录）／`~/.dsh-memory/inject.json`（额外注入清单：把 INDEX 与各项目台账的**绝对路径**列进去，它们才会每轮注入）
4. **库与语料**：会话转写进 `~/.dsh-memory/corpus/` → 切块嵌入 Vault → 会话卡（②层目录）→ 记忆视图（⑧层，给人看）

---

## 二、铁律（违反任何一条都算做错）

- **先读后写**：写任何文件之前先 `read`；**只建不存在的文件**；遇到同名**列出来问用户**，不覆盖、不合并。
- **草案 → 确认 → 落盘**：三份核心记忆**必须先给用户看草案**，他说"行"才写盘。别先写后报。
- **要动他机器的事，先问**：装程序（Ollama / Obsidian）、下模型（约 600 MB）、全量扫会话 —— **一律先说清副作用，他点头才做**。
- **项目清单问用户**：不要替他定边界、也不要替他起名。做法：把扫描到的**疑似项目**列成一句话清单，问他"就这几个吗？分别叫什么？"——**他定了再建**。
- **不许编**：画像/长期记忆里每条都要**有出处**（会话 id 或文件路径）。没有依据的宁可不写。★在每轮注入的画像里编"懂你"是最坏的错误★。
- **扫描范围先问**：默认**只扫当前工作区**的会话。全量很慢（可能一二百份、单份可达几十 MB）→ 先问"要不要连别的也扫"，**分批做、可中断**。
- **每步回写状态**：每做完一步就跑 `init-cli.mjs status` 看一眼 —— **那张卡是靠 `~/.dsh-memory/init.json` 里的状态变 ✓ 的**（`skeleton`/`detect`/`use-api` 都会自己回写）。
- **每步报数字**：扫了多少份、生成了哪些文件、入库多少块。**只说"做好了"不算交付**。
- **失败不许说成成功**：任何一条命令 `exit 非 0`（或 JSON 里 `ok:false`），就把**原文和出路**一起给用户，别糊过去。
- **没做的写"没做"**：不许把没跑的东西写成"全过"。

---

## 三、建议顺序

1. **四问 + 骨架 + 嵌入器 + Obsidian 登记**（第 0 步）—— 卡上前三行变 ✓ 才往下走。
2. **读他给的文档** → 起草三份核心记忆（SOP＝规矩；画像＝他是谁/怎么判断；长期记忆＝跨项目事实与坑）→ **先给草案**。
3. **扫会话**（当前工作区优先）→ 从历史里补充事实/坑/偏好 → 更新草案，并把"从哪份会话看出来的"标在条目里。
4. **问项目清单** → 他确认后，按出厂 SOP 建：`<项目>/PROJECT_LEDGER.md` + `PROJECT_LEDGER_ARCHIVE.md` + `AGENTS.md`，并在根 `AGENTS.md` 里补上地图。
5. **建指针**：`memory/INDEX.md`（项目总目录，一项目一行）／`memory/VAULT_INDEX.md`／`inject.json`（绝对路径）。
6. **入库**：语料转写 → Vault；生成会话卡。
7. **生成记忆视图**：`node "{{PLUGIN_LIB}}/init-cli.mjs" view`（卡上第五行靠它变 ✓）。
8. **打开 Obsidian**（只有第 0 步选了 A/B 才做）：
   `node "{{PLUGIN_LIB}}/init-cli.mjs" obsidian-open` —— 到这一步视图已生成，**树状图/关系图才是完整的**。
   它回 `ok:false` 就照 `hint` 说（没装 / 装哪了 / 也可以直接看文件夹），**别自己编一个"已打开"**。
9. **收尾自检**：`node "{{PLUGIN_LIB}}/init-cli.mjs" status` → 逐条对上面"一、做完的标准"，把结果报给用户（哪几项 ✓、哪几项缺、缺的原因）。

---

## 四、怎么算"用户确认了"

- 草案：**他明确说"可以/行/就这样"** 才算；他沉默、或只说"继续"不算。
- 项目名：他给的名字**原样用**（别自作主张改成英文/短名）。
- 有歧义：**问一句**，别猜（宁可不写，也不要写错——写错的东西会每轮注入给他看）。

---

## 五、完成后对他说什么

1. **生成了什么**（三份核心记忆 / 几个项目文件夹 / 索引 / 入库多少块）——带数字与路径。
2. **还需要他做什么**（例如"某某项目我拿不准要不要单独立文件夹，你定"）。
3. **以后怎么维护**：改当前状态写台账、细节写档案、每次改完跑一次同步（设置页有按钮），想看全貌打开记忆视图。
4. **最后确认卡上 5 行**：跑一次 `init-cli.mjs status`，把 `steps` 里每行的 `ok` 念给他听；**有 ✗ 就说明原因，别含糊过去**。
